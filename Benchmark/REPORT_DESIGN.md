# Benchmark reports: design and data retention

Status: **draft for review.** Items marked **OPEN** need a decision before the cleanup starts.

## 1. Rules

These come from the project owner (2026-10-28). They apply to every benchmark output.

1. Every report is written as CSV. No JSON or Markdown report output.
2. Every report is published as HTML.
3. Every table is published on `index.html`.
4. Every graph and every exploratory analysis is published on `explorer.html`.

**Scope.** A "report" is generated output that holds results. Documentation (README, ADDING_ROLES, this file, `results/LAYOUT.md`) is not a report. **OPEN:** confirm that documentation may stay as Markdown.

## 4. What a run keeps

**Keep (CSV columns):**
- Identity: model tag, params, endpoint, `git_sha`, `harness_version`, `loop_version`, timestamp, `stamp`.
- Per case: pass count `a/b`, attempt results, `superseded` flag (history stays, ranking ignores superseded rows).
- Timing: mean and median seconds per case.
- Resources: peak context tokens, GPU memory, system RAM, shared memory, peak model RAM.
- Failures: infra flag and the failure category (`LoopError`, `TimeoutError`, `APITimeoutError`, `BadRequestError`, `CheckFailed`).

**Drop:**
- Derived values that `build_report.py` recomputes: rank, percentage, score strings, pass-rate bars.
- Per-run Markdown summaries.
- Full model transcripts, **unless** OPEN item 1 says otherwise. I have not yet checked whether the raw JSON contains transcripts; that check comes first.

**OPEN item 1: model transcripts.**
- (A) Drop all. Simplest, smallest.
- (B) Keep only the output of failing attempts, truncated to about 500 characters, in a CSV column. *Recommended:* it keeps the evidence for failures without bloating the store.
- (C) Keep everything in CSV. Large files, hard to read.

## 5. Table design (`index.html`)

One format for every table: ranking, builder, thinker, team, Hard, coding.

| Column | Rule |
| --- | --- |
| Status dot | Round dot: 🟢 all passed, 🟡 some passed, 🔴 none passed, ⚪ not run. Same rule everywhere (`dotOf`, `DOT`). |
| Model | Sticky on scroll, 180px wide. Shows `⚠infra` when the row had infra failures. |
| Params | From `benchmark.csv`. Sticky, 64px. |
| Rank | Position in the table's own order. Sticky, 48px. |
| Score | Square marks: 🟩 all, 🟧 some, 🟥 none, ⬜ NA (`score_cell`, `markF`). Stays square; only the status dot is round. Sticky, 80px. |
| Pass rate % | Number with a bar. Sticky, 110px. This is the last pinned column. |
| Latest run | Date of the newest run. Sits after Pass rate %, so it scrolls. Present on ranking, role, team and Hard tables. |
| Runs | Valid runs per case. |
| Metric columns | Shared memory (role tables), builder/thinker/hard/team scores (ranking), `s/case`, `t/s (info)`, `Run time`, `Valid cases`. |
| Case columns | One per case. Cell: `🟩/🟧/🟥 a/b`. |

**Pinning, all tables (including ranking):** the columns from Dot through Pass rate % are sticky, in that order. Everything after Pass rate % and every case column scroll. Each pinned column has a fixed width, so the case columns start at the same offset in every table. Pinning stops after Pass rate % so that case columns stay visible on a laptop-width screen.

**Frame:** each table sits in a `.tbox` that grows with its content and scrolls horizontally only. The page is full width (`main{width:100%}`).

**Behaviour, all tables:** a filter bar (model name, size, runs-from where the table has dates, show top N); click a header to sort; `Showing N of M` note. The Ranking dropdown starts collapsed; its arrow rotates when open.

## 6. Graph and exploration design (`explorer.html`)

- Every chart reads the same CSV rows as the table it sits beside. No separate numbers.
- Charts: score-band pie, pass-rate bars, size vs pass rate, builder vs thinker, case heatmap.
- Exploratory: Find my model, chart drill-down (click a bar to filter the table).
- Tables that appear on `explorer.html` today break rule 3. See section 7.
