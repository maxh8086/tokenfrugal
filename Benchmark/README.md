## Configuration

Set these in `.env` at the repo root (copy from `.env.example`). Real environment variables override `.env`.

| Variable | Default | Used for |
| --- | --- | --- |
| `LOCAL_LLM_TEMPERATURE` | `0.0` | Sampling temperature for every local model call. Benchmarks need `0.0`; the preflight in `script/run_benchmark.py` fails otherwise. Recorded in each run's `temperature` column |
| `TOKENFRUGAL_LLM_URL` | `http://localhost:11434/v1` | OpenAI-compatible endpoint the benchmark and router call. Overridable per run with `--endpoint` |
| `TOKENFRUGAL_LLM_API_KEY` | `ollama` | API key for that endpoint. Overridable per run with `--api-key-env NAME`, which reads the key from the named variable; the key is never printed or stored |
| `LOCAL_LLM_MAX_TOKENS` | `8192` | Editable in the dashboard settings. The router's tool loop currently caps each reply at 2048 tokens in code, so this value does not change benchmark replies |

`.env.example` documents every variable. The benchmark's own `preflight` step prints PASS or FAIL for each check and the fix to apply.

## Context window and KV cache

Results depend on the context window (`num_ctx`) each model actually ran with, so the test setup fixes it per model.

- **Policy.** `num_ctx = min(native context, 65536)` for models whose native window is above 32768. Models whose native window is 32768 or lower run at 32768 (or at their native size when that is larger, for example 40960). A model with a native window below 32768 therefore runs beyond what it was trained for, and its quality at that size is unverified.
- **The Ollama default is not the test setting.** A Modelfile `num_ctx` overrides the server variable `OLLAMA_CONTEXT_LENGTH`. Without a Modelfile value, Ollama picks a default from free video memory (4096 on an 8 GB card). The router never sets `num_ctx`, so each tested model is a variant with the value baked in; the variant name ends in the context size, for example `-65536`.
- **KV cache cost.** `bytes = 2 x layers x kv_heads x head_dim x bytes_per_value x tokens`, with about 1.06 bytes per value at `q8_0` (`OLLAMA_KV_CACHE_TYPE=q8_0`, `OLLAMA_FLASH_ATTENTION=1`). Very large native windows (262144 to 1048576 tokens) are capped because they do not fit in 31 GiB of RAM.
- **Speed.** A larger context uses more memory, so more layers move from the GPU to the CPU and runs get slower. Check the split with `ollama ps`.
- **Older results.** Runs made before this policy used smaller effective contexts (4096 default, or 16384 for `-16384` variants) and are not comparable with runs that follow it.

## How to read the results

Each row in `results/benchmark.csv` is one run of one model setup, scored on all 81 checks: 27 cases × 3 attempts, across the builder, thinker, hard and coding suites.

| Column | Meaning |
| --- | --- |
| `tag` | Run name, usually the model tag |
| `params` | Model size, for example `3B` |
| `score`, `max` | Passes out of total checks (`score` / `max`) |
| `git_sha` | Commit the run was made from |
| `harness_version` | Version of the cases, scoring and harness (`HARNESS_VERSION` in `run_benchmark.py`). Bump it when they change; rows with different values are not comparable. Empty on older rows |
| `ran` | Number of cases attempted |
| `mean_s_per_case` | Average seconds per case (lower is faster) |
| `total_s` | Whole run time in seconds |
| `compression_level` | How compressed the model file is (`Q4_K_M`: smaller and faster, slightly less accurate) |
| `model_file_size_gb` | Size of the model file on disk, in GB |
| `gpu_memory_used_gb` | GPU memory the loaded model is using, in GB (usage, not capacity; GPU capacity is stated at the top of this file) |
| `shared_system_memory_gb` | Part of the loaded model that did not fit on the GPU and sits in shared / system memory, in GB (0 = fully on GPU; higher is slower) |
| `peak_model_ram_gb` | Highest system RAM the Ollama processes used during the run (this model only, not the whole machine). Empty for older runs |
| `context_window_tokens` | Context window this run used: how many tokens of text the model can hold at once. Not RAM |
| `model_max_context_tokens` | Largest context window the model supports. Not RAM |
| `valid_cases` | Cases that finished and counted |
| `infra_cases` | Cases lost to infrastructure problems (not the model's fault); above 0 is flagged `⚠infra` |
| `mean_s_valid` | Average seconds over valid cases only |
| 16 case columns | One per task, shown as `passed/checks`. See the list below |
| `context_used_<case>` columns | Most context tokens that case used. Not scored |
| `context_used_peak_tokens` | Most context tokens used by any case in the run |

### The two roles

TokenFrugal uses two local models, one per role. A task goes to one of them, never both.

- **Builder** (`qwen2.5-coder-yarn:3b`): writes code and edits files. Needs write and edit tools.
  Cases: `write_function`, `fix_bug`, `write_tests`, `rename_across_files`.
- **Thinker** (`llama3.2:3b-16k`): reads, analyses and browses. Needs read, graph and browser tools.
  Cases: `find_symbol`, `review_sqli`, `debug_trace`, `summarize_readme`, `code_graph_search`, `list_project_files`, `read_docs_file`, `security_file_read`, `design_overview`, `browser_navigate_snapshot`, `plan_status`, `web_crawl`.

The explorer's role table maps each role to its model class and allowed tools (read from `router/tf-roles.yaml`). A case marked `⚠` scored 0 on a case that needs a specific tool, so the tool was likely missing or not called.
