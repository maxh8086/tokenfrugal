# ltx098.json: notes and unverified assumptions

Written without network or a GPU, from memory of the LTXVideo example workflows and the existing
`kalamanch/generators/generate_ltx.py`. Nothing here has been run. Each item below must be checked
against the pinned ComfyUI v0.43.2 and ComfyUI-LTXVideo v1.1.0 in the first real run (Piece 2b).

## What the graph does

Image-to-video, matching `kalamanch/generators/generate_ltx.py` (which is also image-to-video):
512 x 704, 65 frames, 24 fps, seed 42, cfg 1.0, the 8-step distilled sigma schedule from that script,
euler sampler, one clip out.

## Node ids the script relies on

| Id | Role | Found by |
| --- | --- | --- |
| "7" (`RandomNoise`, title `seed`) | seed, input `noise_seed` | `_meta.title == "seed"` |
| "3" (`CLIPTextEncode`, title `prompt`) | positive prompt, input `text` | `_meta.title == "prompt"` |
| "1", "2" | model and text-encoder loaders (load time) | class names `CheckpointLoaderSimple`, `CLIPLoader` |
| "11" (`SamplerCustomAdvanced`) | sampler step time | class name |
| "9" (`ManualSigmas`) | step count (number of sigmas minus 1) | class name |

`comfy_spike.py` finds these by title or class name, not by id, so renumbering is safe as long as
the titles and class names match.

## Verified against object_info (ComfyUI v0.43.2 CPU run, 2026-11-01)

Checked by `GET /object_info` only (no prompt was queued). Every node `class_type` exists, every input
name exists, every link type matches its source output, and the enum values are valid.

* Node classes `CheckpointLoaderSimple`, `CLIPLoader`, `CLIPTextEncode`, `LoadImage`, `LTXVImgToVideo`,
  `RandomNoise`, `KSamplerSelect`, `ManualSigmas`, `CFGGuider`, `SamplerCustomAdvanced`, `VAEDecode`,
  `CreateVideo`, `SaveVideo`: all present in the pinned ComfyUI.
* `CLIPLoader` `type: "ltxv"`: valid enum value.
* `LTXVImgToVideo` inputs and outputs (0 CONDITIONING, 1 CONDITIONING, 2 LATENT): match the links.
* `RandomNoise` input `noise_seed` (INT): valid. `KSamplerSelect` `sampler_name: "euler"`: valid.
* `ManualSigmas` input `sigmas` is a STRING, so the comma-separated form is accepted. Its values are
  not checked for meaning, only for type.
* `CFGGuider` inputs `model`, `positive`, `negative`, `cfg`; `SamplerCustomAdvanced` inputs `noise`,
  `guider`, `sampler`, `sigmas`, `latent_image`: names and link types valid.
* `CreateVideo` (`images` IMAGE, `fps` FLOAT): valid. The integer 24 is accepted for a FLOAT.
* `SaveVideo`: the `format` input is a dynamic combo. Its `auto` option requires a nested `codec`
  input, which is keyed `format.codec` (source: `comfy_extras/nodes_video.py`, dynamic keys joined
  with "."). **Fixed**: the workflow passed a top-level `"codec": "auto"`, which is not the nested key
  and would leave `format.codec` missing. It is now `"format.codec": "auto"`.
* Output key: `SaveVideo` returns its file under `images` (source: `comfy_api/latest/_ui.py`,
  `PreviewVideo.as_dict`). The spike script checks `images` first, so no change was needed.
* `ckpt_name` `ltxv-2b-0.9.8-distilled.safetensors` and `clip_name` `t5xxl_fp8_e4m3fn.safetensors`:
  both appear in the model file lists the container sees. Model file names were not changed.

## Still unverifiable without a run

* `LoadImage` input `image`: the spike sets it from `--image NAME` (default `spike_input.png`). The enum is empty
  until the file is in the input folder, which is `COMFY_INPUT_DIR` when set (else `comfy_data/input`).
  The CPU check found no file there. Place it before running. The spike does not upload it.
* The dynamic-combo flattening (`format.codec`) is confirmed from source, not by a queued prompt.
  The first real run must confirm that ComfyUI accepts it.
* `decode_timestep 0.05` and `decode_noise_scale 0.025` are not reproduced (see below).
* The VAE in the checkpoint is the 0.9.8 VAE, and the quality of the decode, are confirmed only by a run and a human A/B check.
* `t5xxl_fp8_e4m3fn.safetensors` is a present file, but whether it is the correct LTX text encoder is
  not verified (Piece 4 still needs the real repository).

## Not reproduced from generate_ltx.py

* `decode_timestep 0.05` and `decode_noise_scale 0.025`: the VAE decode in this graph is a plain
  `VAEDecode`. A human A/B check (Open Question 7) must confirm the picture is comparable; if not,
  add the timestep-conditioned decode nodes that the pinned LTXVideo version provides.
* The text encoder and the VAE come from the checkpoint (`CheckpointLoaderSimple`) and from `CLIPLoader`.
  `generate_ltx.py` loads `vae_0.9.8` separately. Confirm the checkpoint carries the 0.9.8 VAE.

## Output key

The script looks for the saved file under the `images`, `gifs` or `videos` key of the history entry
(any of them). `SaveVideo` writes `images` (verified from source, see above). Keep the other keys as
fallbacks; `find_output_files` in `scripts/comfy_spike.py` needs no change.
