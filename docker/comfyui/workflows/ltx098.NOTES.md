# ltx098.json: notes and unverified assumptions

Written without network or a GPU, from memory of the LTXVideo example workflows and the existing
`kalamanch/generators/generate_ltx.py`. Nothing here has been run. Each item below must be checked
against the pinned ComfyUI v0.43.2 and ComfyUI-LTXVideo v1.1.0 in the first real run (Piece 2b).

## What the graph does

Image-to-video, matching `kalamanch/generators/generate_ltx.py` (which is also image-to-video):
512 x 704, 65 frames, 24 fps, seed 42, cfg 1.0, the 8-step distilled sigma schedule from that script,
euler sampler, one clip out.

## Node ids the script relies on

| Id | Role | Found by |
| --- | --- | --- |
| "7" (`RandomNoise`, title `seed`) | seed, input `noise_seed` | `_meta.title == "seed"` |
| "3" (`CLIPTextEncode`, title `prompt`) | positive prompt, input `text` | `_meta.title == "prompt"` |
| "1", "2" | model and text-encoder loaders (load time) | class names `CheckpointLoaderSimple`, `CLIPLoader` |
| "11" (`SamplerCustomAdvanced`) | sampler step time | class name |
| "9" (`ManualSigmas`) | step count (number of sigmas minus 1) | class name |

`comfy_spike.py` finds these by title or class name, not by id, so renumbering is safe as long as
the titles and class names match.

## Unverified: node classes and inputs

* `CLIPLoader` with `type: "ltxv"`: the LTX text encoder type string. Verify the enum value in the pinned ComfyUI.
* `t5xxl_fp8_e4m3fn.safetensors`: file name is a guess. Piece 4 needs the real file name and repository.
* `LTXVImgToVideo` inputs (`positive`, `negative`, `vae`, `image`, `width`, `height`, `length`,
  `batch_size`, `strength`) and outputs (0 positive, 1 negative, 2 latent): verify in ComfyUI-LTXVideo v1.1.0.
* `ManualSigmas` (core node in recent ComfyUI, not confirmed): input `sigmas` as a comma-separated string.
  The values are copied from `generate_ltx.py` plus the trailing 0.0. The script's step count assumes
  one sigma per step plus the final 0.0.
* `RandomNoise` input name `noise_seed`: verify (some versions use `noise_seed` on a different node).
* `KSamplerSelect` input `sampler_name` and the `euler` value.
* `CFGGuider` inputs `model`, `positive`, `negative`, `cfg`.
* `SamplerCustomAdvanced` inputs `noise`, `guider`, `sampler`, `sigmas`, `latent_image`.
* `CreateVideo` (input `images`, `fps`) and `SaveVideo` (inputs `video`, `filename_prefix`, `format`,
  `codec`): core video nodes in recent ComfyUI. If the pinned version lacks them, use the
  VideoHelperSuite `VHS_VideoCombine` node only if it is added to the pins (a new pin, not done here).
* `LoadImage` input `image` must be a file in ComfyUI's `input` folder (for example `spike_input.png`).
  The first frame is the same image the kalamanch script uses. The spike does not upload it; place it first.

## Not reproduced from generate_ltx.py

* `decode_timestep 0.05` and `decode_noise_scale 0.025`: the VAE decode in this graph is a plain
  `VAEDecode`. A human A/B check (Open Question 7) must confirm the picture is comparable; if not,
  add the timestep-conditioned decode nodes that the pinned LTXVideo version provides.
* The text encoder and the VAE come from the checkpoint (`CheckpointLoaderSimple`) and from `CLIPLoader`.
  `generate_ltx.py` loads `vae_0.9.8` separately. Confirm the checkpoint carries the 0.9.8 VAE.

## Output key

The script looks for the saved file under the `images`, `gifs` or `videos` key of the history entry
(any of them), because the key for `SaveVideo` is not verified. Adjust `find_output_files` in
`scripts/comfy_spike.py` after the first run if the key differs.
