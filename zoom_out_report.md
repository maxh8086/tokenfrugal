# Zoom Out Report (Stage 5): docs/designs/comfyui-gpu-lease.md

Reviewer: egm-zoom-out, against `zoom-out-standard.md`. Context sufficiency passes: the objective is clear (8 GB of VRAM cannot be shared, so a lease keeps Ollama and ComfyUI apart).

The root idea (one exclusive GPU lease honoured by the router) holds. The document is not simple enough as written.

## Major

1. **Scope: five pieces in one design.** The root problem is "do not load two models into 8 GB". The design bundles that with a supervisor process, an SSE status stream, an ETA estimator with a history file, an embedded editor, a PSNR/SSIM benchmark harness and a pins-schema extension. Only piece 1 plus a container fixes the stated problem. Piece 2b is a go/stop gate, yet pieces 3 and 5 are fully specified before it. Direction: split into (a) lease + pinned container + spike and (b) tab, ETA and tuning, written after 2b passes.
2. **Premature work before the spike.** The ETA design (moving average, per-workflow history) and the tab/bridge are built before anyone knows the model runs in 8 GB. Elapsed time plus ComfyUI's own progress bar in the embedded editor already shows a job is working. Alternative 12 rejects a simple ETA and then builds a complex one. Direction: status as "running, step n/m, elapsed"; add an ETA only if still needed after real use.
3. **Process count and data flow.** `comfy_bridge.py` is a new long-lived Python child spawned by Node (orphan, pid reuse and Node-crash failure modes). Data flows ComfyUI → websocket → bridge → JSON file → Node → SSE → page. `ui/server.js` already shells out. Direction: Node calls a short `python -m router.gpu_lease acquire|release|status` CLI, or polls ComfyUI's `/queue`; drop the websocket unless needed.
4. **Release-on-empty-queue plus heartbeat is the largest complexity driver.** Alternative 5 admits a model reload per job and the debounce is unknown. It forces the bridge and heartbeat into existence. Simpler: the lease is held while the container runs, Stop releases it, and `docker inspect` replaces the heartbeat and TTL. Cost: Ollama is blocked while ComfyUI is up, which may be acceptable since only you start jobs. Direction: start with lease = container lifetime; add auto-release only if idle blocking is annoying.
5. **Lease record over-specified.** Ten fields, `generation`, a lock file with stale-lock logic, `pending`/`held`/`releasing` states and an `ollama` holder, while the same file says the `ollama` holder is not core. `releasing` is never used in the described flow. Direction: one holder, one pid or container id, a timestamp and a task string.
6. **Reuse claim partly wrong or incomplete.** `_alive` exists at `router/compose.py:193`. `stop_all_sync` filters on the project label (lines 179-183), so a separate project is already safe without a `compose.py` edit; keep only the test, or drop both. Importing a private `_alive` across modules is a smell: move it to a small shared util and say so. Check for an existing lock or lease helper before inventing `gpu.lock`.
7. **Router integration and layering.** `loop.py` (line 23, call at 423) and `summarize.py` (line 7, calls at 38, 42) each build their own client, so the Correction section is right, but the earlier "one place" text is still in the Technical Plan and must be fixed in place. `gpu_lease` also holds Ollama unload HTTP code, the VRAM check and the heartbeat, mixing lease state with Ollama control and GPU probing. Direction: `gpu_lease` is state only; the unload helper is separate and reuses the existing `/api/ps` code (`router/preflight.py`, `Benchmark/script/modelinfo.py`).
8. **`kalamanch/run.py` is not the only entry point.** Scripts under `generators/` and `pipeline/` can be run directly and bypass the lease. `run.py` would also import from `router/`, coupling `kalamanch` to the router. Direction: accept this in Non-Goals (as done for direct Ollama clients), or lease inside the generators, and state the package boundary.
9. **Pins schema extension looks like a workaround.** `docker/pins.yaml` already has a `context: folder` pattern where the Dockerfile fetches source and verifies the sha (qdrant-mcp, postgres-mcp). A `nodes:` list, tree-hash checks and changes to `pinned_build.py`, `check_pins.py` and two tests add code to three scripts. Direction: follow the folder-context pattern; keep the node list in the Dockerfile or `SOURCE.md`.
10. **Fail-open default contradicts the safety goal.** A corrupt or expired file while ComfyUI runs lets Ollama through and recreates the original problem. The live check that would compensate is optional and unproven. Direction: if lease = container lifetime, the router can check container state directly (`docker ps` on the label), and the lease file is unnecessary on the router side. State the failure policy once.
11. **Security posture is understated.** The container has outbound network access, unreviewed community nodes and GPU access; the hardening list reads stronger than it is, and Alternative 1 is rejected on isolation grounds while the container has the same node exposure to the mounted models and writable folder. Direction: consider a no-egress network, or state why it was not done and whether the editor needs outbound access.

## Major / Nit

12. **Too many pending decisions for a draft that lists 70+ file edits.** Seven open questions, several about optional features (1, 2), are carried into the file inventory. Resolve or cut them (live check, proxy versus iframe) before listing files.

## Nit

13. **Altitude drops.** Specific values (TTL 30 s, lock stale 10 s, unload wait 60 s, SSIM 0.98 / PSNR 38 dB), the `nvidia-smi` command line, ComfyUI event names, `POST /free` parameters and the `.gitignore` / `docs/technical.md` entries belong in an implementation plan or spike notes.
14. **Document structure.** The "Correction to the Technical Plan" section means the plan is wrong in its own text; fix in place. "You asked for..." mixes conversation voice into a design. The last bullet in Documentation refers to the design itself. Alternatives marked "fixed" cite your decision instead of a reason.
15. **`nvidia-smi` reuse.** `scripts/bench.py` (line 234) and `Benchmark/script/hardware.py` (lines 43-44) already shell out to `nvidia-smi`. Reuse them for the spike and doctor checks. `comfy_spike.py` and `comfy_quality.py` should extend `scripts/bench.py` conventions and the existing Benchmark results layout, not add a parallel CSV format.
16. **Models (piece 4).** The design names `_models.py` and `manifest.py` inconsistently; confirm which holds the manifest (`MODELS` is in `kalamanch/common/manifest.py`, `require()` in `_models.py`).

## Verdict

Simplify: lease = container lifetime, no bridge process and no ETA or tuning pieces until the 8 GB spike passes, reuse the folder-context pin pattern and existing `/api/ps` and `nvidia-smi` code, and fix the single-choke-point inconsistency in the Technical Plan.
